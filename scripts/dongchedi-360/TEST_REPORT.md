## 1.2.0 当前图片复制

- 工具栏顺序为「全屏 → 视角 → 下载 → 复制」，复制使用独立的官方 Lucide 图标和文字按钮，没有下拉面板。
- 复用现有 GM 请求、CDN 与 WebP 完整性校验；复制固定点击时的 URL，在本地转换成原尺寸 PNG，保留透明度。原始 WebP 下载和 ZIP 打包流程不变。
- 点击的同步调用链直接提交 ClipboardItem，PNG 通过 Promise 稍后提供，避免先等待图片请求而丢失用户激活。没有新增 UserScript 权限或运行时依赖。
- 按钮显示「复制中…」与「已复制」，约 1.6 秒后恢复，不另弹成功提示。切换视角、当前帧不明确或复制进行中禁用；错误显示原因，并可重试。
- 颜色、车型、路由、视口变化和页面离开会中止尚在准备的复制；位图和 Canvas 在转换后释放。同一次复制中继续旋转不会改变已选择的帧。

## 本次故障与修复

### 油猴内的原生切换失败

在真实安装脚本的词法作用域中，构造 MouseEvent 并传入 view: window，复现了：

~~~text
Failed to construct 'MouseEvent': Failed to read the 'view' property from 'UIEventInit': Failed to convert value to 'Window'.
~~~

同样的代码在普通页面上下文和部分隔离上下文可成功，所以早期页面实验不能代替完整油猴环境验证。修复为省略非必要的 view 参数，直接向原生容器分时发送鼠标事件。随后在已安装脚本中通过全部八方向以及继续拖拽测试。

自动切换时用户操作会中断脚本并同步释放模拟 mouseup，避免迟到的释放事件终止用户的新拖拽。失败时明确提示，不使用透明度伪造切换，不进入预览层。

### 下载与打包

真站旧版曾在 GM_download 阶段没有回调，45 秒保护超时后解除忙碌状态。1.1.1 改为直接提交浏览器 Blob 下载。随后真实操作暴露了批量图片取完后打包停住的问题；其发生于油猴环境的外部 JSZip 异步生成路径，未将具体库内部原因当作已证明结论。

1.1.2 移除运行时 JSZip 依赖，内置只写 STORE 的标准 ZIP32 打包器，生成 CRC32 和中央目录。最终版的单张、4／8／36 张真站下载均已成功。JSZip 3.10.1 只留在开发端，作为独立读取器验证 ZIP。
